# InsightAT Simple GUI

This is a small Electron shell for the existing InsightAT CLI pipeline. It keeps the user workflow simple:

1. Create or open a work directory.
2. Add one or more image folders.
3. Let the CLI create groups and estimate camera intrinsics.
4. Run SfM reconstruction.

The GUI stores its state in:

```text
<work-dir>/insightat-simple-project.json
```

The real project remains the CLI project:

```text
<work-dir>/project.iat
```

## Run

From this directory:

```bash
npm install
npm start
```

From the repository root, the equivalent command is:

```bash
(cd simple-gui && npm ci && npm start)
```

If the CLI tools are not on `PATH`, set `ISAT_BIN_DIR` before starting:

```bash
export ISAT_BIN_DIR=/path/to/InsightAT/build-cuda-12.8
npm start
```

During local development from this repository, the app also probes common build directories such as `build-cuda-12.8`.

## Packaged GUI

The Docker Linux package build also produces standalone Electron packages for the GUI:

```text
InsightAT-Simple-*.AppImage
insightat-simple-gui_*.deb
```

These packages include the CLI tools and project data generated by the same container build. On a packaged install, the GUI uses the bundled CLI automatically. Set `ISAT_BIN_DIR` before launching only when you want to use a different local build.

To package an existing native build directly:

```bash
INSIGHTAT_BUILD_DIR=/path/to/build-cuda-12.8 \
  ./scripts/package/build_simple_gui.sh
```

When building without network access, provide a cached type-2 AppImage runtime:

```bash
APPIMAGE_RUNTIME_FILE=/path/to/runtime-x86_64 \
  INSIGHTAT_BUILD_DIR=/path/to/build-cuda-12.8 \
  ./scripts/package/build_simple_gui.sh
```

The Docker workflow is preferred because it installs Electron and the native packaging tools inside Ubuntu 22.04:

```bash
./scripts/docker/docker-build-cuda12.8.sh run
```
